# Case To Principle Writing

This skill helps with:

- topic planning
- article framing
- video scripts
- social-phenomenon breakdown
- product and business explanation
- plain-language reasoning

Read these references as needed:

- [references/books-learning-cards.md](references/books-learning-cards.md): book-by-book study cards
- [references/case-selection-rules.md](references/case-selection-rules.md): how to choose and reject analogies
- [references/output-template.md](references/output-template.md): default response format
- [references/safety-rules.md](references/safety-rules.md): anti-hallucination and copyright rules

## Core Workflow

Always work in three stages.

### 1. Source The Case

First ask:

> Which case, model, or classic story from this book set is most structurally similar to the user's problem?

Do not start with abstract advice.

When choosing a case, include:

- source book
- original case
- short case retelling
- why it matches
- match strength: `high`, `medium`, or `low`

If the match is weak, say so clearly.

If no good match exists, do not force one.

### 2. Extract The Principle

After choosing a case, explain:

- surface story
- underlying variables
- core mechanism
- transferable principle
- boundaries
- one-sentence summary

The goal is not "what moral does this story teach."

The goal is:

> what complex problem did the author simplify, and what simple logic did they reduce it to?

### 3. Apply It To The User's Reality

Return to the user's actual task.

Possible outputs:

- clearer viewpoint
- new framing
- writing angle
- opening hook
- argument structure
- title ideas
- memorable lines
- action advice

Unless the user asks otherwise, follow the template in [references/output-template.md](references/output-template.md).

## Case Selection Rules

Use a case only if most of these are true:

1. structural similarity is real
2. the case is easy to retell
3. the principle is clear
4. the transfer helps more than it distorts
5. the user can actually use the result in writing or thinking

Reject the case if:

- it only sounds smart
- the similarity is cosmetic
- it depends on source details you cannot verify
- it produces a misleading causal claim

## Style

Preferred tone:

- clear
- concrete
- story-first
- mechanism-aware
- plain language

Preferred moves:

- begin with the case
- pull out the hidden variable
- connect the variable to the user's world
- turn insight into writing leverage

Avoid:

- generic moralizing
- fake authority
- long unexplained jargon
- using book names as decoration

## Safety

Never fabricate:

- direct quotations
- page numbers
- chapter locations
- "the book explicitly says" when you have not verified the text

When the user wants exact wording from a book, say that you need the actual text.

When the user asks for copyrighted full text or long excerpts, refuse and offer summary instead.
